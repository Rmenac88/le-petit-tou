## 1. Trafic du catalogue (quota Supabase)

Avant : l'accueil retéléchargeait les 789 adresses à chaque lancement, et la Recherche une seconde fois (`select *`).
Après :
- un seul chargeur (`src/lib/catalogLogic.ts`, `src/lib/catalogStore.ts`) partagé par l'accueil, la carte et la
  recherche : **un seul téléchargement par session au plus** ;
- une copie du catalogue est gardée dans un fichier du téléphone ; au lancement, l'appli ne demande que l'empreinte
  du catalogue (`catalog_version()`, migration 022 : environ 50 octets). **Aucun téléchargement si rien n'a changé** ;
  un like ne change pas l'empreinte ;
- hors connexion, la dernière copie sert ; sans migration 022, l'appli fait comme avant (un téléchargement par
  session, mais plus jamais deux).

Estimation (non mesurée sur téléphone) : un jour sans modification du catalogue, le trafic passe d'environ 350 Ko à
moins de 1 Ko par lancement. Les photos ne sont pas concernées : elles restent le premier poste de trafic.

**Le passage en Pro reste conseillé avant la publication** : les photos et une modification du catalogue (qui fait
tout retélécharger une fois par téléphone) restent comptées, et l'offre gratuite peut mettre le projet en pause.

## 2. Changer le code admin (sans qu'il apparaisse dans l'historique du SQL Editor)

Ne pas rejouer `005_admin_secure_writes.sql` en entier (un ancien script ne se rejoue jamais après 006).

1. Choisir un nouveau code de 16 caractères minimum (gestionnaire de mots de passe).
2. Dans un terminal, calculer son empreinte (le code n'est ni affiché ni gardé dans l'historique du terminal) :
   ```bash
   read -rs CODE && printf %s "$CODE" | shasum -a 256 && unset CODE
   ```
   Taper le code puis Entrée : la commande affiche une suite de 64 caractères suivie de `-`.
3. Dans Supabase → SQL Editor, avec les 64 caractères à la place de `EMPREINTE` :
   ```sql
   update public.admin_secrets set value = 'EMPREINTE' where key = 'admin_code_sha256';
   ```
   Attendu : « Success. 1 row affected ».
4. Ouvrir le portail avec le nouveau code. L'ancien doit être refusé.
5. Donner le code aux bénévoles en direct, ou par le gestionnaire de mots de passe, jamais dans un document ni une
   conversation de groupe.
